# Codex와 Claude의 역할을 나누어 협업 준비하기

프로젝트를 작은 학습 단계로 진행하는 방식을 유지하면서, Codex와 Claude Code가 서로 다른 역할을 맡도록 준비하고 있습니다. 2026년 9월 12일 기준으로 역할별 전역 지침 연결, 공통 도구 재사용 확인, Claude Code 기본 권한 설정 적용까지 진행했습니다.

## 역할 나누기

| 담당 | 역할 |
| --- | --- |
| 사용자 | 원하는 작업과 제약을 정하고, 학습 과정에서 질문하거나 다음 단계 진행 의사를 전달 |
| Codex | 요구사항 해석, 학습 단계 설계, 구현 결과의 최종 검토와 학습 문서 관리 |
| Claude Code | 전달받은 범위·제약·완료 기준에 따라 구현하고 필요한 검증 수행 |

Claude의 학습 문서 작성·커밋·푸시는 해당 작업 지시에서 명시한 경우에만 수행하도록 했습니다. 구현과 검토·기록의 담당을 나누어 작업 범위를 분명하게 하기 위한 기준입니다.

## 전역 지침 연결하기

기존 [codex-guidelines 저장소](https://github.com/GimZiHo/codex-guidelines)에 Claude용 `CLAUDE.md`를 추가하고, 두 도구의 지침을 각각 관리하도록 구성했습니다.

```text
~/.codex/AGENTS.md
  → ~/projects/codex-guidelines/AGENTS.md

~/.claude/CLAUDE.md
  → ~/projects/codex-guidelines/CLAUDE.md
```

화살표는 원본 파일을 가리키는 심볼릭 링크입니다. 제 환경에서는 두 경로가 각각의 지침 파일에 연결되어 있는 것을 확인했습니다. 공통 지침 전체를 서로 복사하는 대신, Codex에는 학습 중심 작업 관리 원칙을, Claude에는 구현 담당 규칙을 둡니다.

프로젝트 요구사항과 기술 규칙은 작업 지시에서 원본 위치를 지정해 확인하도록 했습니다. Claude가 프로젝트의 `AGENTS.md`를 참고하더라도 Codex 전용 진행·문서·커밋 절차를 그대로 적용하지 않도록 구분했습니다.

## 결정이 필요할 때와 작업을 마쳤을 때

Claude가 지정 범위 안의 세부 구현은 처리하되, 요구사항 해석이 갈리거나 새 의존성·구조 변경·범위 확대가 필요하면 관련 부분을 멈추고 다음 형식으로 반환하도록 정했습니다.

```text
[결정 필요]
문제: 결정해야 할 사항
선택지: 가능한 접근
추천: 권장 접근과 이유
진행 상태: 완료한 부분과 보류한 부분
```

작업 전달자가 결정을 돌려주면 그 범위에서 재개합니다. 완료 보고에는 완료 여부, 수정 파일, 실행한 검증과 결과, 남은 문제를 담도록 했습니다. Codex는 Git diff로 코드 변경을 검토하고, 새 파일과 중요한 설계 결정은 보고에서 함께 확인하도록 구성했습니다.

## 공통 도구 재사용 확인

Claude의 전역 지침에도 기존 도구와 환경을 먼저 확인하고 재사용하도록 정했습니다. Codex와 같은 `~/.local/share/codex-tools/venv`를 작업 보조용 Python 환경으로 지정하고, 설치 목록과 사용법은 공통 도구 환경 문서를 참고하도록 했습니다.

2026년 9월 12일, 전역 지침 쪽 작업에서 공통 도구 재사용 확인 단계가 완료되었다는 결과를 전달받았습니다. 협업 준비 과정에서 두 도구가 같은 작업 환경을 활용하도록 한 기준을 확인한 단계로 기록합니다.

반복 설치를 줄이기 위한 환경 구성과 관리 원칙은 [공통 도구 재사용으로 반복 설치 줄이기](shared-tool-environment.md)에 정리했습니다.

## Claude Code 기본 권한 설정 적용

역할을 설명하는 지침에 더해, 반복적인 상태 확인은 허용하고 Git 변경 작업은 승인을 요청하도록 기본 권한을 설정했습니다.

| 구분 | 설정한 명령 | 목적 |
| --- | --- | --- |
| 허용 목록 | `git status`, `git status --short`, `git status --short --branch` | 작업 상태 확인 |
| 허용 목록 | `git diff --stat`, `git diff --check` | 변경 규모와 공백 오류 확인 |
| 허용 목록 | 공통 환경 Python의 `--version`, `-m pip show pypdf`, `-m pip check` | 기존 도구와 의존성 확인 |
| 승인 요청 목록 | `git add *`, `git commit *`, `git push *` | Git 변경 작업 전 확인 |

공통 Python 명령은 해당 환경 실행 파일의 전체 경로로 지정했습니다. Python 실행 전체나 패키지 설치, 파일 편집, 모든 테스트 명령을 일괄 허용하는 규칙은 추가하지 않았습니다.

권한 원본은 전역 지침 저장소의 [config/claude-permissions.json](https://github.com/GimZiHo/codex-guidelines/blob/main/config/claude-permissions.json)에서 관리하고, 실제 사용자 설정인 `~/.claude/settings.json`의 `permissions`에 반영했습니다. 이번 기록에서는 실제 설정의 `permissions`와 원본 템플릿이 일치하는 것을 확인했습니다. 관련 커밋은 `eb9643a`입니다.

이 확인은 설정 파일 반영 여부에 대한 것입니다. 명령 규칙은 호출 형태에 따라 적용되므로, 예를 들어 `git push *`만으로 `git -C <경로> push` 등 모든 형태의 Git 작업을 통제한다고 보지는 않습니다. 역할 지침과 권한 설정을 함께 사용하며, 설정에 열거하지 않은 호출까지 모두 차단한 것은 아닙니다.

적용 범위와 새 세션에서의 확인 절차는 [Claude Code 권한 설정 관리 문서](https://github.com/GimZiHo/codex-guidelines/blob/main/docs/claude-permissions.md)에 정리했습니다.

## 현재 준비된 범위

전역 지침 저장소의 `4fd39d5` 커밋에서 Claude 지침과 README의 역할 분담·연결 안내를 추가했습니다. 이 문서는 해당 파일과 실제 심볼릭 링크를 확인해 정리한 설정 기록입니다.

현재 연결은 각 도구가 참고할 지침을 배치한 것입니다. Codex가 Claude를 자동 호출하거나 질문을 자동 전달하는 기능은 아직 구성하지 않았습니다. 지시와 결정은 작업 전달자가 전달하며, 자동 전달 장치가 없는 세션에서는 Claude가 질문을 현재 대화에 반환하도록 했습니다.

실제 협업을 통한 구현·검토 결과는 이후 적용 사례에서 기록할 예정입니다.
