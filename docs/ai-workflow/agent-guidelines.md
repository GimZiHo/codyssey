# 지침으로 AI 작업 방식 조정하기

프로젝트에서 Codex를 활용할 때, 제가 이해하며 따라갈 수 있는 크기로 작업을 나누고 필요한 설명을 받도록 지침을 관리합니다. 이 문서는 2026년 9월 8일 기준으로 사용하는 방식과 그 의도를 소개합니다.

## 지침을 작성한 이유

AI가 기능 하나를 한 번에 구현하면 코드를 이해하며 따라가기 어려울 때가 있습니다. 특히 처음 접하는 메서드나 라이브러리는 어떤 입력을 받아 어떤 결과를 내는지 작은 예제로 확인하며 배우고 싶었습니다.

이런 선호를 작업할 때마다 반복해서 전달하는 대신, 지속적으로 적용할 기준을 `AGENTS.md`에 정리했습니다. 구현 범위와 학습 방식은 제가 정하고, Codex에는 그 기준에 맞춰 구현·설명·검증하도록 요청합니다.

## 전역 지침과 프로젝트 지침

| 구분 | 담는 내용 | 관리 위치 |
| --- | --- | --- |
| 전역 지침 | 작은 단계로 구현하기, 설명과 학습 기록, 커밋·푸시 기준 등 공통 원칙 | 별도의 [codex-guidelines 저장소](https://github.com/GimZiHo/codex-guidelines) |
| 프로젝트 지침 | 해당 프로젝트의 목적과 요구사항, 공통 원칙을 적용할 범위 | 각 프로젝트 루트의 `AGENTS.md` |

제 작업 환경에서는 전역 지침 저장소의 `AGENTS.md`를 `~/.codex/AGENTS.md`에 심볼릭 링크로 연결해 사용합니다. 심볼릭 링크는 원본 파일을 가리키는 연결이므로, 지침을 복사해서 두 군데에서 수정할 필요가 없습니다.

각 프로젝트의 `AGENTS.md`는 별도 파일로 관리합니다. 예를 들어 [이 저장소의 지침](../../AGENTS.md)에는 부트캠프 소개와 생활 팁을 공유하는 정보성 저장소라는 목적을 적었습니다. 프로그램 개발을 위한 전역 규칙은 이 목적에 맞는 경우에만 적용하도록 했습니다.

## 제가 정한 주요 작업 기준

아래는 현재 전역 지침의 핵심을 요약한 내용입니다.

- **작은 단계로 구현하기:** 가능하면 하나의 핵심 개념을 배우고 실행해 볼 수 있는 범위로 나눕니다. 다음 단계는 제 질문과 진행 의사에 맞춥니다.
- **입력과 출력으로 이해하기:** 메서드·라이브러리의 역할, 주요 인자와 반환값, 코드의 실행 흐름을 설명하고 작은 예시나 검증으로 확인하도록 합니다.
- **요구사항에 집중하기:** 과제에 필요한 기능을 중심으로 구현하고, 포트폴리오를 풍성하게 보이게 하려고 구현 범위를 넓히지 않도록 합니다.
- **개념을 기록하기:** 실제 구현에서 다룬 개념과 적용 위치, 확인 방법·결과를 각 프로젝트의 `docs/learning/`에 정리하도록 합니다.
- **작업 이력을 나누기:** 하나의 학습 단계도 검증 후 커밋할 수 있도록 하고, 푸시는 제가 요청할 때 수행하도록 합니다.

이는 AI에 요청하는 작업 기준입니다. 지침에 적었다는 이유만으로 코드의 정확성이나 제 이해가 보장되는 것은 아니므로, 각 단계의 코드와 실행 결과를 확인하고 질문할 수 있도록 구성했습니다.

## 지침을 관리하는 방법

모든 프로젝트에서 바꾸고 싶은 작업 방식은 전역 지침 저장소에서 수정하고 커밋합니다. 특정 프로젝트에서만 필요한 기준은 그 프로젝트의 `AGENTS.md`에 작성합니다.

공통 지침 전문을 이 문서에 복사하지 않고 [관리 중인 원본](https://github.com/GimZiHo/codex-guidelines/blob/main/AGENTS.md)으로 연결합니다. 실제 프로젝트에서의 적용 사례는 해당 코드와 검증 결과를 근거로 별도로 소개할 예정입니다.
