# 공통 도구 재사용으로 반복 설치 줄이기

PDF를 읽는 것처럼 여러 프로젝트에서 반복하는 작업에 필요한 라이브러리를 불필요하게 다시 설치하지 않도록, 전역 지침에 **공통 도구 환경** 기준을 추가했습니다.

설치부터 시작하지 않고 `command -v`로 실행 파일의 위치를 찾고, 기존 가상환경과 버전을 확인해 작업에 적합한 설치를 재사용하도록 했습니다. 가상환경은 Python 라이브러리를 별도로 설치하고 관리하는 공간입니다.

제 환경에서는 작업 보조용 Python 도구를 `~/.local/share/codex-tools/venv`에 모아 관리합니다. PDF 읽기에 사용하는 `pypdf`도 이 환경의 Python을 전체 경로로 호출해 사용하도록 지정했습니다. 설치 위치와 호출 방법을 명시해 다음 작업에서도 같은 환경을 찾을 수 있게 한 것입니다.

- **반복 사용하는 도구:** 지속적으로 유지하는 공통 환경을 사용하고, 호환성 문제나 명시적인 요청 없이 재설치·업그레이드하지 않도록 합니다.
- **일회성 실험:** `/tmp` 설치는 일회성 실험에만 사용합니다. 공통 환경에 쓰기 권한이 없으면 승인을 요청하고, 임시 경로에 다시 설치해 우회하지 않도록 합니다.
- **프로젝트 실행 라이브러리:** 각 프로젝트의 의존성 파일과 환경에서 관리합니다. 프로젝트 실행이 제 개인 작업 도구 환경에 의존하지 않도록 구분합니다.

설치 목록과 버전, 사용 방법, 복구 절차는 [공통 작업 도구 환경 문서](https://github.com/GimZiHo/codex-guidelines/blob/main/docs/tool-environment.md)에 기록합니다. 이곳에서는 반복 설치를 줄이기 위해 정한 기준을 소개하고, 실제 환경 정보는 원본 문서에서 관리합니다.
